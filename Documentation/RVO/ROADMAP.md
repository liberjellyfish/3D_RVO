# 后续步骤与完成条件

各步骤先做小规模正确性，再扩规模；先有可读的参考实现，再优化。P1.0–P1.6 已实现。当前工程验证见 VERIFICATION_P1.md，P1.3 历史基线保留。按本轮范围，正式 100 / 1k / 10k 测试暂缓，Phase 1 整体性能验收与冻结仍待完成。

## P1.0 — 框架（已完成）

已交付数据、模块边界、生命周期、配置入口、检查、测试代码和路线。RVO / ORCA / SpatialHash 后续已完成。不能把框架编译成功算作 Phase 1 已完成。

## P1.1 — 可运行的无避障基线（已完成）

实现 `ScenarioInitializer`、`DirectGoalPreferredVelocity`、`PassThroughSolver`、`PlanarEulerIntegrator`，增加独立 Tick 驱动、基础绘制、暂停/单步/重置，以及一个最小演示场景。

None 和 VO 共用已完成的 BruteForce，保留统一的查询成本和调试数据。场景先实现单 Agent、双 Agent 对向，再补圆周交换、交叉流、对向群体、固定 seed 随机群体。拒绝意外初始重叠或容量不足；重叠恢复测试另建专用场景。

期望速度由目标方向和最大速度给出，接近目标时考虑本步剩余距离，避免到达振荡。到达后保留 Agent 的物理存在；是否移除属于未来明确的策略。

验收：单 Agent 到达、平面不变量、速度上界、不同渲染 FPS 下相同 Tick 结果一致、重置可复现、退出 Play 无原生内存泄漏。None 模式相撞是对照行为，不是避障失败。

## P1.2 — 暴力邻居参考实现（已完成）

实现 `BruteForceNeighborSearch`；先单线程；确定距离边界是否包含端点，按距离/ID 排序、排除自身、统计截断。给定固定输入可独立于运动验证。

验收：0 邻居、单邻居、等距、负坐标、半径边缘、K 截断；与人工/独立枚举集合一致。单个 Agent 的空邻居结果合法。

## P1.3 — VO（已完成）

先写二维速度障碍几何，再实现有限时间视野下的候选速度生成与评价。几何模块不依赖 Unity 场景。加入当前/期望/选定速度和速度障碍的选中 Agent 调试图。

验收：单移动障碍、对向、交叉、追赶、擦边、零相对速度、初始重叠、不同半径/速度；记录碰撞和到达指标。候选采样是近似搜索，披露分辨率与失败情形。

## P1.4 — RVO（已完成）

复用 VO 几何基础，独立实现互惠速度障碍和对应速度选择，保留 VO 作为对照。不要把任意速度平均写成 RVO。

验收：同输入下切换 VO / RVO，比较对称相遇的抖动、速度变化、碰撞和到达时间；构造多 Agent 密集场景，记录仍然存在的震荡和死锁。确定性破对称策略必须可配置并披露。

## P1.5 — ORCA 2D（已完成）

拆为相对运动几何、ORCA 半平面构造、2D 受限速度优化、退化/不可行处理四个内部组件。增加约束可视化，逐项验证法线方向、责任分担、time horizon 与实际 timestep 的用途。

验收：每条满足的约束可数值复核；输出在最大速度圆内；无邻居时返回期望速度；处理平行/相反约束、重合位置、零相对速度和无可行解；与小规模独立参考或 RVO2 结果对照，允许明确容差，不要求轨迹逐位一致。

完成 None / VO / RVO / ORCA 的统一场景回归矩阵。之后才进行高密度规模测试。

## P1.6 — Spatial Hash（已完成）

实现建桶、范围枚举、精确过滤、最近 K 选择、确定性排序和截断统计。BruteForce 始终保留为正确性参考。

验收：跨 cellSize / 查询半径 / seed / 负坐标 / 边界的属性测试，与 BruteForce 最近 K 集合及排序一致；包括查询半径大于 cellSize 的情况。测量候选数和桶占用，确认实际收益及密集退化情形。

## P1.7 — 100 / 1k / 10k 压测与诊断（工具已交付，正式压测未执行）

实现 benchmark runner、warmup、重复试验、阶段计时、质量采集、CSV + JSON 报告、运行元数据和纯仿真模式。World 已采集总计时与主线程分配；BenchmarkRunner 支持显式预热、重复、阶段计时、独立质量检查、CSV / JSON 和运行元数据。正式规模完整矩阵、Player 及端到端报告仍待执行。

先测 100 的完整算法矩阵，再做 1k 和 10k。10k 的主路径使用 Spatial Hash；暴力模式作为可选的耗时参考，不能为了跑完删除安全检查而不记录。

验收：每档有原始报告、机器和构建信息、P50/P95/P99、分阶段耗时、GC、内存、截断率与质量指标。所有场景满足约定的质量要求；性能结论采用实测，不预先承诺 10k 的 FPS。

## P1.8 — 按瓶颈优化并冻结 Phase 1（小规模优化已完成，规模验收与冻结待办）

根据 32 / 64 Agent 的阶段计时，已优化采样方向缓存、持久 scratch、Jobs / Burst、一次渲染帧只上传一次 Mesh 与圆盘方向缓存；参考实现与质量对照保留。后续正式 P1.7 仍需重新定位规模瓶颈，不能外推当前结果。每次优化保持旧实现可比，并重新跑相关质量回归。

验收：至少一份前后对照报告；解释速度提升是否来自牺牲质量；重复开关场景无泄漏；Player 中的结果可复现到指定容差。达标后冻结 Phase 1 公共契约，再进入 Phase 2。

## Phase 2 — 网格导航与静态/动态避障协同（吞吐与局部安全优化已实现）

后续一轮已增加局部通行优先级、主动侧让/后退、临时拥堵代价、失败重试和终点标记优化；小规模双后端与六 agent 单车道验证见 [PHASE2_TRAFFIC.md](PHASE2_TRAFFIC.md)。它们降低常见堵塞，不替代完整预约或普遍无死锁保证。

1. 已实现单层占据、半径净空、连通域与不可变版本地图。
2. 已实现 ALT + 可调权重 A*、直线捷径、精确 A* 对照、四上下文预算与直达快速路径。
3. 已实现按实际长度租用 waypoint、Burst 几何跟随/错峰前瞻、版本/请求状态、目标变更取消旧搜索。
4. 已实现离线烘焙、合并矩形 BVH、组合求解 Burst、独立扫掠查询与局部连通分量退让；静态平面在动态无解时保持硬约束。
5. 已加入可切换动态 KDTree、查询等价测试和吞吐对照，见 [规划](PHASE2_PLAN.md) / [本轮验证](VERIFICATION_P2_OPTIMIZATION.md)。

后续：复杂窄道优先级/预约交通管理、路径规划 Job 化、共享/分层图、完整墙段几何，以及 Player 正式性能矩阵。当前不保证任意拥堵都能消解；本轮 16/256/1024 Editor 对照不能替代 100/1k/10k 正式验收。

## Phase 4 — Sparse Voxel Navigation Volume

Voxelization → Clearance → Connectivity → 3D A* → 可通行性约束下的 Path Smoothing → Preferred Velocity → 3D ORCA。

每层保留输入输出及地图版本：占据体素不等于可导航体素；有净空不等于连通；路径平滑后仍需净空检查；局部 ORCA 不修复不可达的全局路径。先静态地图离线构建，再考虑局部重建、流式加载和异步路径请求。
