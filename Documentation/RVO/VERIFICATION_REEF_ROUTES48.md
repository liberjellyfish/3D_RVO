# 水纹去重复与 48 障碍路线验证（2026-10-05）

> 历史专题记录：下文的默认参数、实现状态和测试数字对应文中日期及当时版本。当前系统结构与运行配置见 [ARCHITECTURE.md](ARCHITECTURE.md)，最新主场景证据见 [2048 多通路报告](VERIFICATION_REEF_NETWORK2048.md)。

本轮完成焦散空间采样改造、48 障碍礁石场景与离线导航重建，以及 1024 agents 的新旧地图测量。现有 A*、启发式权重、搜索预算、ORCA 参数与 agent 档位不变。JPS 和更高 agent 数量留待下一阶段。

## 焦散

- 保留 Hoskins/joltz0r 的 `CausticRaw` 数学公式、共享 R16F 双时间纹理与 30 Hz 更新。原公式不是严格周期的，因此只改边界包装：两端各 5% 的对称重叠替代原末端 10% 的单侧拉平。
- `OceanCommon.hlsl` 的统一入口使用等边三角网格，每个顶点拥有固定的旋转和偏移，三个纹理片段连续混合。随机值只依赖世界投影坐标，不依赖相机、物体或时间。岩石、海床、鱼身继续共享原光线投影。
- 两张时间纹理使用相同变换；旋转后的显式梯度送入 `SampleGrad`，避免随机分区导致错误 mip。纹理链显式分配全部 mip。
- 三次幂归一化权重降低普通线性混合的对比度损失，不加亮度增益、不做负值截断。这是简化的随机采样，不是完整的 Heitz 直方图保持算法，也不声称严格保持纹理分布。
- `OceanEnvironment.StochasticCaustics` 默认开启，可关闭以对照重复采样。共享模式每个接收点由 2 次基础纹理采样增加为 6 次；生成频率与纹样的世界尺度不变。

512×512 GPU 线性读回，覆盖 8×8 个原纹理周期，三个时间点的 D3D11 结果：

| 时间 | 平均亮度变化 | 标准差保留 | 原周期相关性：重复 → 随机 |
| --- | ---: | ---: | ---: |
| 0 s | +0.42% | 84.6% | 1.000 → 0.0004 |
| 4 s | +0.22% | 82.7% | 1.000 → −0.0007 |
| 7.25 s | −0.08% | 83.8% | 1.000 → −0.0239 |

这里的标准差描述亮纹对比度，约有 15%–17% 的衰减，未靠提高材质焦散增益掩盖。原周期的强重复已被打散。GPU 检查还覆盖：完整 mip 数量、远处降频、三角网格跨边界连续性、纹理周期边界、时间插值与空间混合的交换一致性、有限且非负的输出。测试夹具单独初始化 URP 的 `_GlobalMipBias`；裸 `Graphics.Blit` 的默认零值曾使测试错误地强制使用 mip 0。

证据：`Verification/ReefRoutes48/Caustics/Direct3D11/metrics.csv` 及同目录 PNG。截图与 CPU 测量不能用来推断 GPU 帧时间；本轮没有独立 Player GPU 性能结论。

## 路线与地图

场景：`Assets/RVO/Demo/OceanReef/OceanReefLive.unity`。仍为 64 m 立方体、128³、0.5 m 细体素、4 m 粗体素，最大体型与安全间距继续用于保守烘焙。

48 个代理的构成：原有 20 个海床/礁石主体，加 16 个高位洞口块体、8 个下层通道侧礁、4 个错位短挡板。新增结构都在两端出生带内侧。

- 高位支路位于 `x=±16, z=±21`，四组洞口有交替高低的底槛，经中央礁冠上方连接；保留南北两个方向的通行选择。
- 下层侧礁位于 `x=-12,-5,5,12, z=±6`。短挡板左右错开，低位直行会被阻断，可以走 S 形绕行或上升越过挡板。
- 障碍沿 X 较薄，区间留有缓冲空间；没有把全程做成长窄管道。
- 主礁冠 X 尺寸由 26 m 缩为 22 m，保留两侧可重新连接网格节点的空间。
- 可通行细体素从 854,526 降至 805,246。48 是总代理数量，包含海床与外围大礁，不是 48 堵独立全高墙。

中间布局暴露了一个已有几何隐患：agent 117 到达 `(-12.46719, 7.959142, -4.373017)` 后，位置无碰撞但 `Anchor=-1`，不断得到 `InvalidEndpoint`。旧礁冠与西侧石柱形成不足一个体素宽的缝隙。缩短礁冠后该位置可以连接网格；最终三次运行均无此停滞。保留 `Final48` 和 `Diagnosis48` 作为复现证据，正式结果以 **Accepted48** 为准。

烘焙器同时处理 Windows 下已加载 `.bytes` 的内存映射锁：卸载旧 TextAsset，写完整临时文件，再替换原文件与同步导入。

## 1024 agents 的正式对照

环境：Unity 6000.0.63f1，i7-12650H，Editor Jobs/Burst，同步 Burst 编译，seed 7，30 Hz；每张地图各 3 次 × 1800 ticks。独立 16-agent 世界预热，每次重新解码地图。计时不包含渲染和质量采样；阶段计时会完成各阶段 Job。统计覆盖首批请求和后续运行，没有丢弃启动尾延迟。

| 指标 | 原 20 障碍 | 最终 48 障碍 |
| --- | ---: | ---: |
| Tick P95（3 次范围） | 6.887–6.985 ms | 7.549–7.676 ms |
| Tick P99（3 次范围） | 14.871–15.272 ms | 18.334–18.562 ms |
| 导航阶段均值（3 次平均） | 0.692 ms | 0.866 ms |
| 邻居查询均值 | 2.869 ms | 2.920 ms |
| 避碰阶段均值 | 0.833 ms | 0.949 ms |
| 积分均值 | 0.026 ms | 0.027 ms |
| 首路径 P50 / P95 / 最大等待 | 0.900 / 1.900 / 2.567 s | 1.033 / 2.000 / 2.600 s |
| 60 秒内首次/当前到达 | 1024 / 1024 | 1024 / 1024 |
| 最长连续低速等待 | 1.767 s | 1.900 s |
| 请求总数 / 粗图成功 / 细图回退 | 2717 / 1599 / 5 | 3579 / 2413 / 5 |
| 扩展节点总数 | 144,549 | 149,998 |
| 静态扫掠违规（逐 Tick） | 0 | 0 |

| 主线程 Tick 托管分配 | 0 B | 0 B |

同一布局三次运行的到达、请求、回退、扩展和安全计数一致。最终第 1 次运行在 tick 1028（约 34.27 s 仿真时间）全部到达。

测得的瓶颈有不同时间尺度：

1. **平均耗时主要在邻居查询**：约 2.92 ms，占四阶段均值之和约 61%。只替换寻路器不会移除这部分成本。
2. **启动尾延迟主要在导航**：最终第 1 次的前 90 ticks，Tick P95 22.04 ms；最慢 tick 61 为 24.62 ms，其中导航 19.54 ms、扩展 4096 节点。去掉前 90 ticks 后 P95/P99 为 7.29/8.75 ms。因此全程 P99 的上升与首批搜索有关。
3. **周期性导航工作值得继续细分**：内部每 15 tick 的协调时刻，导航平均 2.66 ms，其余时刻 0.76 ms（第 1 次全程统计）。代码包含交通恢复全体扫描，这与周期相符；当前阶段计时未将交通恢复与其他导航工作分开，不能把差值全部归因于它。
4. **当前地图没有导致粗图大规模失效**：最终回退仍为 5 次。该结论限于本次地图、seed 与体型设置。

这是 Editor 无渲染的 1024-agent 测量，不是整帧/GPU 预算，也不是 2048/4096 agents 的性能承诺。成对安全仅每 30 ticks 抽样，零计数不等于逐 tick 的成对安全证明；静态扫掠则每 tick、每 agent 检查。

## 重现

> 当前脚本的 Profile 调用最新 OceanReefBuilder 与最大档，会生成 96 m / 192³ / 2048 多通路配置，不能直接复原本页的旧 20/48 障碍对照。严格复现须恢复本报告对应的代码、Profile 和地图；脚本的 Tests/Capture 仍可用于当前版本的相关检查。详情见 [当前验证指南](VALIDATION.md)。

关闭本项目的 Unity 实例后，在项目根目录运行 `Documentation/RVO/RunReefRoutes48.ps1`，使用尚不存在的输出目录：

```powershell
./Documentation/RVO/RunReefRoutes48.ps1 -Stage Profile -Output Documentation/RVO/Verification/ReefRoutes48/Reprofile
./Documentation/RVO/RunReefRoutes48.ps1 -Stage Tests -Output Documentation/RVO/Verification/ReefRoutes48/Retest -Api d3d11
./Documentation/RVO/RunReefRoutes48.ps1 -Stage Capture -Output Documentation/RVO/Verification/ReefRoutes48/Recapture -Api d3d11
```

`Profile` 会重新生成场景与导航资产；`Tests` 执行导航和 GPU 检查；`Capture` 连续输出近景、俯视、斜视、实景以及关闭随机采样的俯视对照。采样图像测试证据默认写入 `Caustics/<API>`。

原始性能证据：`Baseline20` 与 `Accepted48` 的 `summary.csv`、逐 Tick `curve-*.csv`、逐 agent `agents-*.csv` 和 `environment.txt`。中间试验目录不是正式性能结论。
